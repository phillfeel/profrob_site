# Страница «Решения» (/solutions/) — дизайн-концепция (v2, упрощённая)

Статус: черновик на согласование. Контент и SEO — из ТЗ (страница 3). Здесь только внешний вид.

---

## 1. Идея

Спокойная страница-каталог: крупный заголовок, сетка из девяти белых карточек (пока без картинок), ниже блок ссылок-сценариев, две карточки «Смотрите также» и тихая форма обратной связи. Красота за счёт крупной типографики, иконок, воздуха и аккуратного hover. Никакой новой анимационной механики: только то, что уже есть на главной (`.reveal` при появлении, подъём карточки на hover).

Правила консистентности:
- Светлая `--surface` с зерном, графитовый `--stage` только точечно: полоса «Гуманоидные роботы» и последняя карточка «Состава».
- Белые карточки `--r-lg`, `--shadow-sm` → `--shadow-md` и подъём 2px на hover (как `.task` и `.case`).
- Onest, mono только для индексов и цифр. Заголовки — утверждения с точкой.
- Один синий акцент на экран, лайм точечно. Без шильдиков `[ • X ]`, только индекс `02 — НАПРАВЛЕНИЯ`.
- Счётчик разделов справа остаётся, контент не заходит в `--rail`.

## 3. Секции

### 01 Hero

```
01 — РЕШЕНИЯ
Направления роботизации:                     ┌───────────────────────┐
от клининга до гуманоидов.                      │ 9 направлений         │
                                             │ 2–5 производителей    │
Мы собираем решение под задачу из            │ на каждое             │
оборудования разных производителей…          └───────────────────────┘
```

- Высота по содержимому (около 60vh), не на весь экран.
- Слева H1 (`clamp(36px, 4.6vw, 72px)`, две строки) и вводный текст: первый абзац — `lead`, второй обычным телом, фраза «Робот без сервиса быстро встаёт» весом 600.
- Справа стеклянная карточка по образцу `.metrics` с двумя фактами из ТЗ. Других цифр не выдумываем.
- Анимация: стандартный `.reveal`.

### 02 Направления — сетка карточек

Без картинок. Карточка строится как `.task` с главной: иконка в `--accent-soft`, номер, название. Это уже готовый паттерн, нового CSS почти нет. Бенто на 12 колонок, девять карточек, клининг крупнее остальных:

```
┌───────────────────────────┐ ┌─────────────┐ ┌─────────────┐
│ [иконка]              01  │ │ [ик.]    02 │ │ [ик.]    03 │
│                           │ │             │ │             │
│ Роботизированный клининг  │ │ Складская…  │ │ Сервисные…  │
│ описание из ТЗ            │ │ описание ↗  │ │ описание ↗  │
│ [Быстрая окупаемость]  ↗  │ └─────────────┘ └─────────────┘
└───────────────────────────┘ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
┌─────────────┐ ┌───────────┐ │ 06 Строит.  │ │ 07 Агро     │ │ 08 Безопасн.│
│ 04 Промышл. │ │ 05 Мед.   │ └─────────────┘ └─────────────┘ └─────────────┘
└─────────────┘ └───────────┘ ┌──────────────────────────────────────────────┐
                              │ 09 Гуманоидные роботы — под конкретный запрос │
                              └──────────────────────────────────────────────┘
```

Точная раскладка уточняется при вёрстке; важно: клининг в двойную ширину и высоту, гуманоиды широкой полосой снизу, остальные одинаковые.

Устройство карточки:
- Сверху: иконка 56px в плитке `--accent-soft` (линейная, stroke 1.75, как у `.task .ic`) и номер в mono справа.
- Внизу: название (`heading-l`, у клининга крупнее), одна строка описания из ТЗ (`ink-muted`), круглая стрелка ↗ в правом нижнем углу.
- Вся карточка — одна ссылка `<a>`.
- Hover: подъём 2px, тень `--shadow-md`, стрелка заливается синим. Больше ничего.
- Клининг: лаймовый бейдж «Быстрая окупаемость» (из ТЗ). Единственный лайм на экране.
- Гуманоиды: тёмная полоса `--stage` с названием и пометкой «Под запрос».
- Картинки добавим позже отдельным шагом: в карточке остаётся место под рендер сверху, поэтому вёрстка не переделывается.

Иконки: девять простых линейных иконок (уборка, склад, сервис, завод, стройка, медицина, поле, щит, человек). Берём из того набора, что уже используется в карточках задач на главной, недостающие рисуем в том же стиле.

Появление: карточки получают `.reveal` с небольшой ступенчатой задержкой (50ms на карточку), как строки отраслей.

### 03 Что можно автоматизировать

```
03 — СЦЕНАРИИ
Что можно автоматизировать.

[ Уборка ] [ Доставка ] [ Перемещение грузов ] [ Патрулирование ] [ Инспекция ]
[ Обслуживание гостей ] [ Строительство и отделка ] [ Реабилитация и уход ] [ Уход за территорией ]
```

- Девять pill-ссылок (`--r-pill`, белые, высота 48px, иконка слева), переносятся на несколько строк. Без бегущей ленты.
- Hover: фон `--accent-soft`, текст `--accent-ink`. Это обычный hover кнопок.
- Каждая pill ведёт на соответствующее решение или отрасль.
- Слева заголовок и короткий лид, справа блок pills (двухколоночная сетка 5fr/7fr, как в «Отраслях»).

### 04 Состав решения

Четыре белые карточки в ряд: «Подбор оборудования», «Интеграция», «Обучение людей», «Сервис по SLA». У каждой номер, иконка в `--accent-soft`, заголовок и одна фраза. Последняя карточка на `--stage` — это наше отличие. Стрелки между карточками статичные. Мобильная версия — вертикальная колонка. Без анимации линий.

### 05 Смотрите также

Две крупные белые карточки 1:1: «Отрасли» (подпись «5 ОТРАСЛЕЙ», ниже пять названий через точку: Сервис и клининг · Строительство · Медицина и велнес · Промышленность · Сельское хозяйство) и «Продукты» (роботы и платформа, ниже названия через точку). Hover как у всех карточек: подъём и стрелка.

### 06 Форма обратной связи — тихая

Форма живёт на этой же странице, чтобы клиент оставил контакты и ему перезвонили, не переходя никуда. Она должна быть заметной, но не конкурировать с выбором направлений: поэтому стоит в самом конце, без тёмного фона и без крупного заголовка.

```
Не уверены, какое решение нужно?            ┌────────────────────────────────┐
Оставьте контакты. Перезвоним,              │ Имя            [__________]    │
зададим пару вопросов и подскажем.          │ Телефон        [__________]    │
                                            │ Что автоматизировать ▾ (необяз.)│
Или сами рассчитайте окупаемость →          │ ☐ согласие на обработку данных │
                                            │ [ Заказать звонок ]            │
                                            └────────────────────────────────┘
```

- Две колонки 5fr/7fr, как в «Отраслях». Слева заголовок размером `display-m` (меньше обычных H2 страницы) и лид, ниже текстовая ссылка «Рассчитать ROI» на `roi.html`. Справа белая карточка `--r-lg`, `--shadow-sm`.
- Поля: имя, телефон (обязательные), «Что автоматизировать» — выпадающий список из девяти направлений плюс «Пока не знаю» (необязательное), чекбокс согласия. Три поля, не больше.
- Кнопка «Заказать звонок» — `.btn-pri`. Синей заливки на экране в этот момент больше нет, а hover-стрелки карточек выше уже за границей экрана.
- Состояния: ошибка у поля словами, отправка (кнопка блокируется, спиннер), успех («Заявка принята. Перезвоним в рабочее время.»), сбой сети с возможностью повторить.
- Валидация Zod на клиенте и на сервере, скрытое honeypot-поле против ботов, маска телефона. Токены и ключи только через env.
- Если форму открыли из карточки направления, выбор в списке можно проставить автоматически позже, на лендингах направлений.

### Страницы направлений: блок «Где применяется»

Для будущих страниц `/solutions/[slug]/`. Связь отрасль ↔ решение двусторонняя: лендинг отрасли ведёт на решение, страница решения — обратно на отрасли.

```
ГДЕ ПРИМЕНЯЕТСЯ
Сервис и клининг — внутренний клининг ↗   Сервис и клининг — улица ↗   Медицина и велнес ↗
```

- Строка компактных ссылок `see-card` уменьшенного размера или текстовых ссылок со стрелкой, перед формой.
- Каждая ссылка ведёт на лендинг отрасли с якорем направления (`/industries/service-cleaning/#street-cleaning`).
- Анкор — название отрасли и направления, а не «роботы для …», чтобы не перебивать запросы самой страницы решения.
- Соответствие решений и отраслей — в `СПЕКА_ОТРАСЛЕВОЙ_ЛЕНДИНГ_ДИЗАЙН.md`, раздел 2.

## 4. Разметка и SEO

- Один H1, H2 по секциям: «Девять направлений. Одна задача — ваша.», «Что можно автоматизировать.», «Из чего состоит решение.», «Смотрите также.»
- Title, Description, вводный текст, названия и описания направлений — дословно из ТЗ.
- Всё кликабельное — обычные `<a>`, страница работает без JS.
- Schema.org: `ItemList` из девяти направлений и `BreadcrumbList`.
- URL только английскими словами, без транслита. Страница хаба: `/solutions/` (в ТЗ стоит `/resheniya/`, заменяем). Направления: `/solutions/cleaning/`, `/solutions/warehouse/`, `/solutions/service-robots/`, `/solutions/industrial/`, `/solutions/construction/`, `/solutions/medical/`, `/solutions/agro/`, `/solutions/security/`, `/solutions/humanoid/`. Соседние разделы: `/industries/`, `/products/`.

## 5. Адаптив и доступность

- 1280+ — сетка из описания выше.
- 768–1279 — карточки по две в ряд, клининг на всю ширину, «Состав» 2×2, форма под заголовком в одну колонку.
- до 767 — одна колонка, карточки направлений компактнее (иконка слева, текст справа), pills переносятся, форма на всю ширину.
- Hover ничего не скрывает: всё доступно по тапу. Цели не меньше 44px, штатный `:focus-visible`, `prefers-reduced-motion` отключает `.reveal`.
- Поля формы с `label`, `autocomplete`, `inputmode="tel"`, ошибки связаны через `aria-describedby`.
