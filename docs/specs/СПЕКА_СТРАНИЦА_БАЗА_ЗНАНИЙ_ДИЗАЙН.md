# Страница «База знаний» (/knowledge/) — реализация и открытые вопросы

Дата: 2026-10-07. Файлы: `knowledge.html`, `knowledge.css`, `knowledge.js` (фильтр, поиск, раскрытие ответа по якорю); общие скрипты — `solutions.js` (появление, счётчик, форма). Контент и SEO — ТЗ v2.1, страница 7 (`docs/archive/initial-docs/ТЗ_ПРОФРОБОТ_контент_сайта_v2_1 -ВСЕ СТРАНИЦЫ.docx`); темы материалов — информационные запросы ядра (раздел II, п. 2.3–2.6).

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| URL | `/knowledge/` (файл `knowledge.html`) | английские слова (правило проекта); в ТЗ стоял `/baza-znaniy/` |
| Тип страницы | SEO-хаб: разделы → материалы → FAQ, без самих статей | статьи — батч 6 ТЗ, их ещё нет. Придумывать статьи с цифрами нельзя |
| 12 категорий ТЗ | сетка карточек. Основная ссылка фильтрует материалы (`?topic=<slug>`), вторая ведёт на коммерческую страницу направления (решение, продукт RaaS, калькулятор, производители) | ТЗ: «Категории ссылаются на соответствующие решения и отрасли» |
| Материалы | 14 тем по инфо-запросам ядра, статус «Готовится», строка не ссылка | честное состояние. Когда статья появится, строка становится ссылкой `/knowledge/<slug>/` и теряет статус |
| Поиск | по тексту материалов и FAQ на текущем языке, все слова запроса, ё = е; совпавшие ответы FAQ раскрываются | хаб на 23 элемента без поиска неудобен; без JS всё видно |
| «Новости рынка» | карточка с нулём материалов, фильтр показывает пустое состояние с CTA «Задать вопрос» | раздел есть в ТЗ, контента нет |
| ROI-калькулятор (обязательный блок) | тёмная сцена: формула окупаемости, три правила расчёта, кнопки на `roi.html` и на методику `cases.html#method` | формула та же, что в методике кейсов |
| FAQ (обязательный блок) | 9 вопросов-аккордеонов `<details>`, 5 главных — в оглавлении hero. Ссылка `#faq-…` раскрывает ответ. JSON-LD `FAQPage` совпадает с разметкой (проверяет тест) | возражения из ТЗ: дорого, сломается, окупаемость, переучивать |
| Ссылки на страницу | подвал главной (была заглушка `#`) | в шапке 7 пунктов, база знаний туда не добавлена, как и в макете |
| Schema.org | BreadcrumbList + FAQPage. `Article` — на будущих страницах статей | ТЗ, раздел III |
| Индексация | `noindex`, как у остальных прототипов | — |

## Откуда тексты ответов FAQ (проверить)

Ответы собраны из того, что сайт уже утверждает. Новых цифр нет.

- Окупаемость: **срок не назван**. В ТЗ (пример JSON-LD, раздел III) стоит «обычно 12–24 месяца», но это пример разметки, а у конкурентов разброс от 18 мес. до 3 лет (`docs/research/2026-10-02-roi-competitors.md`). Нужна цифра клиента.
- Аренда, лизинг, Retrofit — тексты страницы «Продукты» и главной.
- Сервис по SLA, своя сеть по России, AI-агенты — страница «Услуги», ТЗ п. 1.2.
- Персонал «переходит на другие задачи» — методика кейсов. Список задач (санузлы, точечная уборка, контроль качества) — из кейса бизнес-центра, плюс «контроль качества» от меня.
- «2–5 производителей» — ТЗ п. 1.2.
- AMR и AGV — общее определение, не утверждение о компании.
- «Когда не окупается» — мой вывод из логики расчёта, клиент не подтверждал.

## Открытые вопросы к клиенту

1. **Срок окупаемости робота-уборщика** для ответа FAQ: диапазон и условия (площадь, смены).
2. **План статей**: 14 тем — черновик по ядру. Подтвердить порядок, первые 3–5 статей и авторов.
3. **Раздел «Новости рынка»**: нужен ли на старте? Пустой раздел можно скрыть.
4. **Ответ «Когда не окупается»** и список задач персонала — подтвердить.
5. **Страницы решений** (`/solutions/cleaning/` и т. п.) пока не существуют, как и на «Кейсах»; ссылки разделов заработают вместе с ними.

## Страница статьи (2026-10-07)

Файлы: `knowledge-cleaning-robot-basics.html`, `knowledge-article.css`, `knowledge-article.js`; переводы `i18n/en.partial/kbCleaning.json`; тест `node tools/playwright/knowledge-article.mjs`. URL в проде: `/knowledge/cleaning-robot-basics/`.

- **Шаблон**: hero с ответом в первых строках + паспортная карточка модели → липкое оглавление и колонка текста → заявка. Блоки текста: `.ar-parts`, `.ar-steps`, `.ar-split`, `.ar-calc`, `.ar-limits` (тёмный), `.ar-check`, FAQ (`.kb-q`), источники. Новая статья = копия файла с новыми ключами `kb<Тема>.*`.
- **Хаб**: строка материала 01 стала ссылкой (`.kb-item--live`, маркер «Читать» вместо «Готовится»). Остальные 13 по-прежнему «Готовится».
- **Фактура**: цифры только по паспорту Gausium Phantas (gausium.com/specs, /products, /technology, открыты 2026-10-07), в статье названы источником. Расчёт «≈ 1 600–3 100 м² на заряде» = 4,5 ч × 350–700 м²/ч, помечен как наш. Границы 3 500 / 10 000 м² взяты из `roi-model.js`. Блоки «Остаётся людям» и «Когда не подходит» помечены в тексте как инженерная оценка.
- **Расхождение источников**: в поисковой выдаче «теоретическая» производительность Phantas указана как 950/1 180 м²/ч, на официальной странице — 1 188/1 674. Теоретическую цифру в статью не берём; «практическая» 350–700 совпала в обоих.
