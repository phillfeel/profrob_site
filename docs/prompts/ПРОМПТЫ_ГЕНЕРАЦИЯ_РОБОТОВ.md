# ПРОФРОБОТ — промпты для генерации роботов героя

**Дата:** 2026-09-29
**Задача:** заменить плоский растр `assets/podium.jpg` (2048×710, всё запечено в один слой)
на набор отдельных изображений роботов с прозрачным фоном, пригодных для послойной анимации
в героe главной.
**Куда идёт результат:** `assets/robots/` → нарезка `rembg` → слои в `.podium` (`index.html:418`).

---

## 1. Решения, принятые до генерации

### 1.1 Генерируем по-роботно, не сценой целиком

| Причина | Суть |
|---|---|
| Разрешение | В сцене 2048px каждый робот ~300px шириной. Для hover `scale 1.06` на ретине нужно 1000–1400px на робота. |
| Нарезка | Робот на плоском фоне без тени режется `rembg` в один клик. Из общей сцены — ретушь края у каждого. |
| Перегенерация | Неудачный робот перекатывается один, а не вся сцена с пятью удачными. |
| Консистентность | Достигается дословно одинаковым техническим блоком промпта, а не общим кадром. |

**Масштаб между роботами из генератора не вытягиваем.** Каждый заполняет свой кадр,
соотношение размеров выставляется в CSS вручную. Это единственное требование, с которым
генератор стабильно не справляется, — снимаем его с него.

### 1.2 Логотипы в изображение не попадают никогда

Нейросеть не рисует корректный бренд-знак: буквы плывут, знак получается «похожим».
Единственный способ получить правильные логотипы — держать их отдельным SVG-слоем поверх сцены.
Поэтому в промпте стоит жёсткий запрет на любой текст, шильдики и декали, включая логотип ПРОФРОБОТ.

**Решено:** официальные логотипы лежат в `assets/brands/` (обработанные) и
`assets/logos_official_bundle_updated/logos/` (исходники). Прежние заглушки из `homepage/logos/` удалены.

### 1.3 Роботы = отрасли, логотипы = отдельный блок

Сейчас под роботами идёт плинтус из 7 чипов брендов, что читается как «эти бренды делают этих
роботов». Это неверно:

| Категория | Кто это на самом деле | Есть в списке 7 брендов |
|---|---|---|
| Агро — дрон-опрыскиватель | DJI Agras, XAG | нет |
| Стройка — демонтажный робот | Brokk, Husqvarna | нет |
| Уборка — поломоечная машина | Gausium, Pudu, Keenon | да |
| Производство — манипулятор | UR, Fanuc (Hikrobot — машинное зрение) | почти нет |
| Склад — AMR | Hikrobot, ForwardX | да |
| Велнес — массажное кресло | — | нет |

ТЗ (стр. 254) называет DJI, XAG и Brokk драйверами спроса наравне с Pudu/Gausium/Keenon,
а логотипы производителей (стр. 384) описывает как **отдельный блок** с подписью
«Работаем с ведущими мировыми производителями».

**Значит:** роботы на подиуме — по отраслям; логотипы — отдельной строкой ниже.
Исчезает ложное соответствие и необходимость впихивать 7 чипов под 6 роботов.

### 1.4 Правовая заметка

Генерация «реалистичной модели конкретного производителя» — это двойник чужого продукта.
Для дилерского сайта корректнее официальные рендеры из медиакита вендора: они бесплатны
для партнёров и юридически чисты. Промпты ниже — рабочий вариант, если медиакит недоступен.
Поэтому в них описан **тип техники**, а не конкретная модель конкретного бренда.

### 1.5 Фон — средне-серый, не светлый

**Проверено на первой партии.** Изначально в спеке стоял фон `#F3F2EF` под цвет страницы.
Это ошибка: корпуса роботов белые, и на тёплом светлом фоне белый бак дрона отстоял от фона
всего на **6.5 единиц** при собственном шуме фона 0.6. Цветового зазора практически нет.

Последствие: обычная вырезка «по расстоянию до цвета фона» — и `rembg` в том числе — съедает
белые панели, корпус уходит в серые пятна. Первая партия спасена вырезкой через заливку
от рамки кадра (фон определяется связностью с краем, а не похожестью цвета), но это
обходной путь.

Поэтому в техническом блоке стоит `#8C8C8C`. Фон всё равно удаляется, его цвет на результат
не влияет, а запас по контрасту с белым корпусом делает нарезку тривиальной.

---

### 1.5 Подиум не генерируем

Тёмная эллиптическая плита с синим кантом и отражением собирается на CSS:
`border-radius` эллипсом, `linear-gradient` на торце, `box-shadow` для свечения,
отражение через `::after` с `scaleY(-1)` и маской. Кольца свечения под роботами —
`radial-gradient`, тогда они смогут реагировать на ховер вместе с роботом
(запечённые в растр кольца этого не умеют).

## 4. Приёмка кадра

Отбраковывать сразу, не копить:

1. **Фон идеально ровный** — пипеткой одно значение по всем четырём углам. Любой градиент
   или остаточная тень = перекат, чистой альфы из такого не выйдет.
2. **Ни одной буквы, цифры и значка на корпусе.** Генераторы любят подрисовать шильдик —
   это первое, что надо искать.
3. **Ракурс три четверти влево у всех роботов набора.** Один смотрящий прямо или вправо выпадет
   из ряда, на подиуме это сразу видно.
4. **Объект не касается края кадра** — иначе при вырезании получим срез.
5. **Опора внизу читаемая** (гусеницы, колёса, лыжи) — робот должен уметь «встать» на подиум,
   а не висеть в воздухе.
6. **Для 07 — ровно шесть колёс, все на одной плоскости, без «лица» и без надписей.**
   Генераторы рисуют этот класс то с четырьмя колёсами, то с восемью, а на пустой боковине
   любят писать DELIVERY. Пара фар, которая читается как глаза, и красный или оранжевый флажок
   тоже перекат: это фирменные черты Яндекса и Starship. Мачта должна быть цельной от крышки
   до флажка. Тонкую мачту проверяем после вырезки отдельно: если она порвалась, кадр в работу не идёт.
7. **Для 08 — пять пальцев на каждой руке, обе стопы на земле, экран без лица.** Гуманоиды
   у генераторов ломаются в кистях и коленях; лишний палец или подогнутая нога = перекат.
   Должны читаться черты GR-1: яйцевидная голова-визор, П-образная синяя ручка на поясе,
   длинные обтекаемые бёдра. Мягкая обивка (как у GR-3) или чёрный корпус = перекат.

## 5. Что дальше

1. Сгенерировать 6 кадров, прогнать по чек-листу раздела 4.
2. `rembg` → PNG с альфой → конверт в WebP с альфой (цель 50–80 КБ на робота).
3. Подписи категорий `[ АГРО ]` и т.д. перенести в HTML (SEO, чёткость на ретине,
   отдельная анимация).
4. Подиум — на CSS (раздел 1.5), логотипы — отдельной строкой ниже сцены.
5. Собрать песочницу с режимами движения: «Спотлайт» / «Конвейер» / только ховер.
