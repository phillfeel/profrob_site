# i18n: сообщения сайта ПРОФРОБОТ

Русский текст остаётся в разметке. Каждая строка, которую читает посетитель, помечена атрибутом `data-i18n*` и ключом. `i18n/ru.json` не пишется вручную: его собирает `tools/i18n/extract.mjs` из страниц и генератора. Английский (`i18n/en.json`) подставит рантайм (этап M2). Формат словаря совпадает с next-intl: вложенный JSON, плюралы и подстановки в ICU MessageFormat, в ключах нет точек. Страницы переедут на Next.js вместе со словарём.

## Файлы

| файл | что это |
|---|---|
| `ru.json` | все русские сообщения, вложенный JSON. Генерируется, руками не правится |
| `en.json` | английские сообщения (делает Агент 2). Те же ключи, те же переменные и теги |
| `js.ru.json` | русские сообщения, которые есть только в JS (пространство `js.*`). Правится руками, входит в `ru.json` |
| `context.json` | для переводчика: роль строки, где стоит, переменные, ограничение по ширине. Генерируется |
| `context.notes.json` | заметки для переводчика, написанные руками (ключ или шаблон ключа → текст) |
| `js-sites.md` | где в JS стоит каждая строка (файл:строка): рабочий список для M2 |
| `glossary.md`, `style-guide.md` | терминология и стиль английского (Агент 2) |

Инструменты лежат в `tools/i18n/`: `extract.mjs` (сборка словаря), `check.mjs` (проверки), `coverage.mjs` (текст без ключа), `icu.mjs` (разбор и подстановка ICU, без зависимостей), `html.mjs` (маленький читатель HTML). Для проверки вёрстки до и после правок разметки есть `tools/playwright/snapshot.mjs`.

## Схема ключей

Ключ — путь в JSON, сегменты через точку: `[A-Za-z0-9_-]+`, точек внутри сегмента нет, имена в camelCase.

| пространство | что в нём |
|---|---|
| `common.*` | шапка, подвал, форма, крошки, названия решений и ссылок, общие источники: всё, что стоит на нескольких страницах |
| `home.*`, `solutions.*`, `roi.*` | рукописные страницы: `<страница>.<секция>.<что>`, например `home.hero.title`, `home.tasks.items.cleaning.title` |
| `calc.*` | типы объектов и режимы уборки калькулятора (`calc.types.office`, `calc.modes.one`): одни и те же на ROI-странице, на отраслевых и в JS |
| `industries.common.*` | общая оболочка отраслевых страниц: названия секций, заголовки по умолчанию, мини-калькулятор, форма |
| `industries.<страница>.*` | одна отрасль: `industries.retail.problems.items.2.title`. Страница в camelCase: `businessCenters`, `medicalWellness`, `publicSpaces`, `fitnessSports` |
| `js.*` | строки, которые собирает JS: `js.<модуль>.…` |

Правила:

- Строки из данных генератора получают ключ по пути в данных (`problems[2].title` → `problems.items.2.title`). Элемент списка, у которого есть `id` или `key`, называется по нему: `levels.roof.name`.
- Строка из шаблона (написана прямо в коде страницы) получает явный ключ: `industries.<страница>.<секция>.<что>`.
- Один ключ — один текст, на всех страницах. Если смысл или роль разные (кнопка «Связаться» в шапке и кнопка формы, «Кейсы» в навигации и метка секции), ключи разные, даже когда русский текст совпадает. Если одно и то же имя стоит на многих страницах (названия решений, продуктов, услуг), ключ общий: таблица `NAMES` в `tools/industries/build.mjs`.
- Метка секции («ПРОБЛЕМЫ») — одно сообщение и для `data-name` секции, и для тега `NN — МЕТКА`, и для счётчика.

## Разметка

| атрибут | значение |
|---|---|
| `data-i18n="ключ"` | содержимое элемента — обычный текст (`textContent`). Дочерних элементов быть не должно |
| `data-i18n-html="ключ"` | содержимое — текст с встроенными тегами из списка ниже |
| `data-i18n-attr="alt:ключ;aria-label:ключ2"` | сообщения для атрибутов: `alt`, `title`, `aria-label`, `placeholder`, `content` (у `<meta>`), `data-name`, `data-cat`, `data-res` |
| `data-i18n-args='{"n":3}'` | значения переменных для сообщений с `{n}`: страница статична, числа известны при сборке |

Один элемент — одно сообщение. Если в элементе рядом с текстом стоят значки, `<svg>`, `<i></i>`, числа с анимацией (`data-count`) или другие элементы, которые нельзя трогать, текст заворачивается в `<span data-i18n="…">` (или `<bdi data-i18n="…">`).

Обёртки не должны менять вид страницы. Три источника проблем, все нашлись при проверке:

1. CSS стилизует `span` в этом контексте (`.stk-logo span`, подвал `.foot-status`): ставьте `<bdi>`, у него нет стилей на сайте.
2. Родитель — flex-ряд с `gap` (`.ih__aud`, `.drow__sol`, `.btn`): два соседних куска текста стали бы двумя flex-элементами, и появился бы лишний зазор. Весь ряд заворачивается в один элемент: `<span><span data-i18n>Решение:</span> <span data-i18n>название</span></span>`.
3. Селекторы `:first-child`, `>`, `+` и JS, который читает `textContent` родителя.

Проверка: `node tools/playwright/snapshot.mjs --out <папка>` до правок и после, затем `--compare <до> <после>`: сравнивает каждое слово с его положением и шрифтом, атрибуты и рамки всех элементов (`span` и `bdi` без класса не считаются). Снимок другого состояния сайта: `--root <папка с копией сайта>` (например, `git archive <коммит> | tar -x -C <папка>`).

### Теги в сообщениях

Разрешены: `a`, `b`, `br`, `button`, `em`, `i`, `mark`, `small`, `span`, `strong`, `sub`, `sup`, `u`. В сообщении у тега нет атрибутов. Правило подстановки для рантайма: тег сообщения соответствует n-му элементу с тем же именем в русской разметке этого узла и берёт его атрибуты (`class`, `href`). `<br/>` и пустые элементы пишутся самозакрывающимися. Переводчик может переставлять слова и теги, но не терять их и не добавлять новые. В `js.*` атрибуты тегов (например, `type="button" data-retry` у `<button>`) задаёт код, как `t.rich()` в next-intl.

Нельзя `<a href>` внутри сообщения, нельзя вложенные списки. Всё остальное: пробелы между словами схлопываются как в HTML, неразрывные пробелы пишутся как ` ` в JSON.

### ICU

Поддерживаются: `{name}`; `{n, number}` и `{n, number, ::.0}` (формат числа по языку, число знаков после запятой); `{n, plural, one {…} few {…} many {…} other {…}}` (`#` — число, `=0 {…}`, `offset:1`); `{n, selectordinal, …}`; `{x, select, a {…} other {…}}`; теги. В русском три формы плюрала плюс `other`, в английском `one` и `other`. Кавычки как в ICU: `''` — апостроф, `'{'` — буквальная скобка. `date` и `time` не нужны и не разбираются. Разбор проверен на всех сообщениях эталонным парсером `@formatjs/icu-messageformat-parser` (в проект он не добавлен).

Сообщения с переменными на статичных страницах: в разметке стоит русский результат, рядом `data-i18n-args`, шаблон лежит в `TEMPLATES` (`tools/industries/build.mjs` или `templates` страницы). Русский текст генератор получает из шаблона, поэтому разойтись они не могут; `check.mjs` сверяет разметку с шаблоном (пробелы не в счёт: между группами цифр бывает отдельный элемент).

## Как добавить строку

Рукописная страница (`index.html`, `solutions.html`, `roi.html`): поставьте атрибут и ключ в разметке, русский текст оставьте как есть. Затем:

```bash
node tools/i18n/extract.mjs --write     # обновит ru.json и context.json
node --test tools/i18n/check.mjs        # проверки
```

Отраслевая страница: правится `tools/industries/data.mjs` или `tools/industries/pages/<страница>.mjs`, не HTML. Ключи ставят помощники из `build.mjs` (передаются в рендереры как `h`): `h.T(obj, 'поле')` — ключ по пути в данных; `h.L('путь')` — свой литерал страницы; `h.C('имя')` — общий литерал оболочки; `h.K('ключ')` — любой ключ; `h.TH`, `h.LH`, `h.CH`, `h.KH` — то же для сообщений с тегами; `h.TA(['alt', ключ])` — атрибуты; `h.TN(ключ, текст)` — ключ только если текст зависит от языка; `h.msg(ключ, args)` — сообщение с переменными. Константы страницы, которые показывает рендерер (источники, расписания), отдайте в `data: { … }` экспорта модуля, иначе у них не будет пути для ключа. Затем:

```bash
node tools/industries/build.mjs && node tools/i18n/extract.mjs --write && node --test tools/i18n/check.mjs
```

Строка из JS: добавьте её в `js.ru.json`, место вызова впишите в `js-sites.md` (первая ячейка строки таблицы — ключ в обратных кавычках), затем `extract.mjs --write`.

## Проверки

`node --test tools/i18n/check.mjs` (и `node --test tools/i18n/icu.test.mjs` для разборщика):

1. разметка читается, один ключ — один текст, шаблоны совпадают с разметкой;
2. нет текста, зависящего от языка (кириллица, ₽, десятичные запятые, группы тысяч, даты `дд.мм.гггг`), без ключа; тексты, которые пишет скрипт (`data-count`, `data-out`, часы, `aria-valuetext`), не считаются;
3. `ru.json` и `context.json` совпадают с тем, что извлекается из страниц (дрейф);
4. отраслевые HTML совпадают с выводом генератора (никто не правил сгенерированный файл);
5. каждый ключ из разметки есть в `ru.json`, лишних ключей нет; ключи `js.*` есть в `js-sites.md`, и наоборот;
6. все сообщения — валидный ICU, теги только из списка;
7. имена ключей;
8. у кнопок, ссылок меню, подписей, пунктов списка, заголовков H1 и меток секций есть заметка в `context.json`;
9. если есть `en.json`: те же ключи, те же имена переменных и теги, валидный ICU, нет кириллицы (проверить другой файл: `I18N_EN=путь node --test tools/i18n/check.mjs`).

`node tools/i18n/coverage.mjs` перечисляет места без ключей. `node tools/i18n/extract.mjs --duplicates` показывает один и тот же русский текст под разными ключами: их переводят одинаково, если нет причины (контекст, ширина).

Репетиция смены языка: `node tools/playwright/snapshot.mjs --out <папка> --lang ru` подставляет `i18n/ru.json` в разметку в браузере (теги по правилу слотов, переменные из `data-i18n-args`) и снимает страницу. Если словарь и разметка согласованы, снимок равен снимку без `--lang` (так проверено на всех 14 страницах при 1440 и 390 px). С `--lang en` тот же скрипт покажет, как английский сел в вёрстку. Элементы, текст которых пишет roi.js (`#r-k2-l`, `#staff-hint`, `#r-net-u`), репетиция пропускает: после смены языка их перерисовывает сам скрипт.

## Рантайм (M2): что нужно знать

Рантайм заменяет содержимое по ключу из `en.json`, раскладывает `data-i18n-attr`, подставляет `data-i18n-args` и меняет `lang` у `<html>`. Русский вариант он запоминает из DOM при первой замене (запрос за русским словарём не нужен). Тонкие места (клоны роботов в `main.js`, метка счётчика, переформатирование чисел, `industry-business-centers.js`) перечислены в `js-sites.md`. JSON-LD и `<html lang>` рантайм не трогает: английский не индексируется.
