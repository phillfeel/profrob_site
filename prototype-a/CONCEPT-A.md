# ПРОФРОБОТ — Прототип главной, вариант A «Конвейер»

**Статус:** прототип для согласования движения и ритма (не продакшен).
**Дата:** 2026-09-26
**Файлы:** `prototype-a/index.html` (один файл: HTML + CSS + JS), `prototype-a/assets/` (podium.jpg, логотипы).
**Источники:** контент — `ТЗ_ПРОФРОБОТ_контент_дистиллированный.md` (v2.1, раздел IV «Главная»); визуал — `design-system/README.md`, `design-system/tokens.json`, эталон `design-system/assets/Reference/hero-reference.png`.
**Родственный вариант:** `prototype-c/index.html` — концепция C «Центр управления» (см. раздел 9).

---

## 1. Суть концепции

Страница листается вниз нативно. Отдельные блоки «доезжают» до верха экрана, закрепляются (pin), и дальнейший скролл вниз двигает их содержимое **справа налево**. Когда лента закончилась — блок отпускается, страница идёт дальше. Метафора — линия сборки: остановка → операция → дальше.

Поверх — «приборный» слой из дизайн-системы: счётчик разделов `01 / 08` справа, живые цифры в виджете мониторинга.

Итоговая формула (рекомендация из обсуждения): **A как основа + наезд на подиум из концепции B + приборный слой из концепции C.**

## 2. Непреложные правила (для всех вариантов)

| Правило | Почему |
|---|---|
| Скролл нативный, без scroll-jacking (не перехватываем колесо, не делаем «слайды») | Core Web Vitals (INP, CLS) из ТЗ 3.2, доступность, трекпады |
| Весь контент — в HTML; ленты = CSS-transform поверх обычной разметки | Индексация Яндексом, H2 и тексты карточек видны роботу |
| Анимируем только `transform` и `opacity` | Нет перерасчёта layout, нет CLS |
| Движение по токенам: `ease-standard` cubic-bezier(.2,0,0,1), `duration-slow` 600ms, сдвиг 16px, без пружин | Дизайн-система, раздел «Движение» |
| `prefers-reduced-motion` → закрепления сняты, счётчики сразу финальные | Доступность |
| Мобайл (<1024px) → нет pin; ленты = свайп-карусели на `scroll-snap`; счётчик разделов скрыт | Производительность и UX на телефонах |
| Максимум 3 закреплённые сцены на страницу | Больше — утомляет, ломает ритм |

## 3. Карта разделов (как реализовано)

Счётчик — **01 / 08** (по ТЗ главной 8 блоков; футер с цифрами не нумеруется). В дизайн-системе заложено 09 (Роботы, ROI, FAQ) — **открытый вопрос**, см. раздел 8.

| # | Блок (ТЗ) | id | Поведение | Реализация |
|---|---|---|---|---|
| 01 | Hero | `#hero` | Появление текста каскадом; подиум всплывает; цифры `142 / 14 / 98,2` отсчитываются; при скролле подиум «наезжает» (scale 1→1.18, y+60), текст уходит вверх с затуханием | GSAP timeline, `scrub: true`, start `top top` → end `bottom top` |
| 02 | Задачи (6 карточек) | `#tasks` | **Pin + горизонтальная лента.** Слева заголовок закреплён и закрыт фоном, справа 6 карточек + 7-я тёмная CTA «Подобрать решение» едут справа налево. Шкала прогресса `01 / 06` | `[data-hpin]`, `x: -dist()`, `pin`, `scrub: 1`, `invalidateOnRefresh` |
| 03 | Внедрение (6 шагов) | `#process` | **Pin + горизонтальный таймлайн.** Синяя линия прорисовывается (`scaleX` = progress), узлы шагов загораются по очереди (`.step.on`), неактивные — opacity .35 | `[data-hpin][data-timeline]`, тот же механизм + onUpdate |
| 04 | Результат (5 KPI) | `#results` | Тёмная сцена (`Stage` с `glow-edge`). Без pin. Цифры отсчитываются, лаймовые шкалы заполняются каскадом при входе | ScrollTrigger `once`, count-up 1.4s |
| 05 | Кейсы (4) | `#cases` | Горизонтальный слайдер без pin: свайп/трекпад + стрелки + счётчик `01 / 04`. Фото — заглушки | нативный `overflow-x` + `scroll-snap` |
| 06 | Отрасли (12) | `#industries` | Заголовок `position: sticky` слева, список 12 строк справа. Hover: сдвиг строки, синяя стрелка. SEO-метки (AMR, ДЕМОНТАЖ, АГРОДРОНЫ) у приоритетных | CSS sticky + reveal |
| 07 | Платформа (6 функций) | `#platform` | **Pin, скроллителлинг.** Слева список функций, справа мок интерфейса (HTML, не скриншот): карта объекта, роботы со `ScanRing`, KPI-карточки. Скролл переключает функции → интерфейс подсвечивает свою зону (зоны качества, алерт, графики) | pin на `feats.length × 55%` высоты экрана; `data-f` на `.ui` |
| 08 | Финальный CTA | `#contact` | Тёмная сцена по центру, только появление. Кнопка ROI, телефон/почта, 3 элемента доверия | reveal |
| — | Футер | `footer` | 5 цифр доверия с count-up | ScrollTrigger `once` |

**Сквозные элементы:**
- Навигация-таблетка (стекло), фиксированная; активный пункт подсвечивается по разделу.
- `SectionCounter` справа: номер, синяя шкала, вертикальная подпись раздела; на тёмных секциях — тёмная тема (`.on-dark`).
- Зерно на фоне (SVG fractalNoise, opacity .035).
- Плашка «ПРОТОТИП · A «КОНВЕЙЕР»» слева внизу — убрать в продакшене.

## 4. Технический стек прототипа

| Что | Версия / источник | Зачем |
|---|---|---|
| GSAP + ScrollTrigger | 3.12.5, jsDelivr | pin, scrub, горизонтальные ленты |
| Lenis | 1.1.13, jsDelivr | сглаживание инерции скролла (связан с ScrollTrigger через `gsap.ticker`) |
| Шрифты | Onest + JetBrains Mono, Google Fonts | по дизайн-системе |
| Иконки | инлайн SVG (штрих 1.75, Lucide-стиль) | без зависимостей |

**Ключевые технические решения (важно перенести в Next.js):**
1. **Порядок пересчёта триггеров.** Pin-триггеры создаются не сверху вниз, поэтому им задан `refreshPriority` (Задачи 3, Внедрение 2, Платформа 1) + `ScrollTrigger.sort()` + `refresh()` после загрузки шрифтов и картинок. Без этого все триггеры ниже первой ленты съезжают.
2. **Активный раздел** считается одной функцией на скролле: «последняя секция, чей верх выше середины экрана» через `getBoundingClientRect`. Работает корректно и для закреплённых секций (отдельные триггеры на секциях ломались на pin-блоке платформы).
3. **Закрытие ленты заголовком:** `.hpin-head` с фоном `surface` и `box-shadow: -60vw 0 0 60vw` + градиент-фейд справа — карточки уезжают «под» заголовок. На мобайле отключено.
4. **Дистанция ленты** = `track.scrollWidth − (ширина окна − левый край viewport) + 80px`, пересчитывается на resize (`invalidateOnRefresh`).
5. Все pin-анимации внутри `gsap.matchMedia('(min-width:1024px) and (prefers-reduced-motion:no-preference)')` — на мобайле и при reduced-motion их просто нет.
6. **Фолбэк:** если CDN с GSAP не загрузился — все `.reveal` показываются, цифры проставляются финальные; страница полностью читаема.
7. Якоря навигации идут через `lenis.scrollTo()` (с учётом pin-спейсеров).

**Ассеты:** `podium.jpg` — вырезка нижней части эталонного рендера (1586×600, JPEG q86). Логотипы партнёров «запечены» в картинку.

## 6. Проверено / не проверено

**Проверено** (встроенный браузер, 1440×900 и 375×812):
- все pin-секции, горизонтальные ленты, таймлайн, переключение функций платформы;
- счётчик разделов и подсветка навигации совпадают с реальным положением секций;
- count-up в герое, результатах и футере;
- на мобайле нет горизонтального скролла страницы; ленты — свайп;
- ошибок в консоли нет.

**Не проверено:**
- Safari (macOS/iOS) и реальные телефоны — там pin и Lenis чаще всего капризничают;
- производительность на слабых Android;
- Lighthouse / Core Web Vitals.

## 7. Известные замечания и идеи доработки

- Наезд на подиум — это масштаб плоской картинки. Настоящий эффект из концепции B («из 6 роботов в фокусе остаётся клининговый») требует секвенции ~40 кадров рендера или отдельных PNG роботов на прозрачном фоне → нужен запрос на рендеры.
- Параллакс роботов по глубине невозможен, пока подиум — одна картинка. Нужны слои: подиум / каждый робот / метки `Tag`.
- Длина закрепления «Задач» ≈ 2,6 экрана — возможно, стоит сократить (меньше ширина карточек или убрать 7-ю CTA-карточку).
- Мок интерфейса платформы — упрощённый; для продакшена нужен реальный скриншот или согласованный макет.
- Нет ROI-калькулятора, FAQ, блока «Роботы» (есть в ДС, нет в ТЗ главной).
- Претензии пользователя к визуалу и анимациям — **ещё не собраны**, ожидается список (см. раздел 11).

## 9. Вариант C «Центр управления» — чем отличается

Файл: `prototype-c/index.html` (копия A + блок CSS-оверрайдов + новый скрипт без библиотек).

| | A «Конвейер» | C «Центр управления» |
|---|---|---|
| Закрепления | 3 (Задачи, Внедрение, Платформа) | нет |
| Задачи | горизонтальная лента | сетка 3×2, ячейки собираются каскадом |
| Внедрение | горизонтальный таймлайн | вертикальный трек, заполняется по скроллу |
| Герой | наезд на подиум | статичный подиум, «живые» цифры мониторинга |
| Платформа | функции переключаются скроллом | автопереключение, пока блок на экране + клик |
| Приборный слой | счётчик разделов | счётчик + плашка телеметрии (раздел · % скролла · время) |
| Зависимости | GSAP, ScrollTrigger, Lenis (~45 KB) | ноль (IntersectionObserver + один rAF-обработчик) |
| Вау-эффект | высокий | средний |
| CWV / SEO | хорошо | отлично |

Элементы C дешёвые и накладываются на A — гибрид возможен без переделки.

## 10. Путь к продакшену (Next.js)

**Стратегия «дешевле всего»:** согласовать движение на этом HTML-прототипе → сразу Next.js, без промежуточных прототипов (Figma-анимации, Webflow и т.п.).

**Почему Next.js подходит:** Яндексу нужен готовый HTML в ответе сервера. App Router + статическая генерация (SSG) для главной и 12 отраслевых лендингов; текст рендерится на сервере, анимации — клиентские островки.

**Архитектура:**
- `app/` — App Router, SSG (`generateStaticParams` для отраслей), metadata API для Title/Description/OG/canonical из ТЗ 2.5 и 3.2.
- Токены `design-system/tokens.json` → CSS-переменные + тема Tailwind.
- Компоненты ДС (`design-system/components/*`: NavBar, SectionCounter, Stage, Tag, Kpi, CaseCard, IndustryCard, Segmented, Slider, Accordion, Footer…) → React-компоненты (TS strict).
- Анимации — `'use client'` компоненты с `@gsap/react` (`useGSAP`), логика из раздела 4 переносится как есть; `gsap.matchMedia` сохраняем.
- Контент — сначала типизированные данные в коде (TS + Zod), CMS — позже.
- Schema.org JSON-LD (Organization, BreadcrumbList, Service, FAQPage) — серверно.
- Фото — `next/image`, AVIF/WebP, приоритет только у подиума (LCP).

**Порядок работ:** токены + компоненты → главная (перенос анимаций) → шаблон отраслевого лендинга → ROI-калькулятор (ТЗ, раздел VII) → остальные страницы.

## 11. Показ и процесс правок

**Где показывать (код в браузере скрыть нельзя — можно только закрыть доступ к сайту):**

| Вариант | Цена | Доступ |
|---|---|---|
| Artifact на claude.ai | бесплатно | приватная ссылка, делится по желанию; обновления — по той же ссылке. Самый дешёвый путь сейчас |
| Cloudflare Pages + Cloudflare Access | бесплатно до 50 чел. | вход по email из белого списка. Лучший вариант для заказчика |
| Vercel / Netlify с паролем | платно (Pro) | по паролю; удобно для Next.js |
| GitHub Pages | — | не подходит: сайт публичный |

**Экономный процесс правок:**
1. Собрать все претензии **одним** сообщением: пронумерованный список по блокам 01–08, при необходимости со скриншотами.
2. Формулировать результат, а не процесс («02: лента длинная — сократить вдвое», «герой: убрать зум»).
3. Правки — точечные `Edit` по строкам, без переписывания файла.
4. Визуальную проверку делает пользователь (скриншоты агента дорогие).
5. Мелочи можно править самим: цвета/размеры — блок `:root` в начале файла, тексты — прямо в HTML.
6. Для точечных правок достаточно более лёгкой модели / низкого reasoning.

**Локальный запуск:**
```bash
python3 -m http.server 4173 --directory prototype-a
```
(или просто открыть `index.html` двойным кликом; конфиг превью — `.claude/launch.json`, `prototype-a` на 4173, `prototype-c` на 4174).
