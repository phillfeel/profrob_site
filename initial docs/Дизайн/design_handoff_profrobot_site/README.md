# Handoff: сайт ПРОФРОБОТ — типовые страницы

## Overview
Предварительный дизайн корпоративного B2B-сайта компании **ПРОФРОБОТ** (интегратор роботизации и автоматизации бизнес-процессов). Пакет содержит **12 типов страниц**: для каждого повторяющегося типа — один готовый макет с единой дизайн-системой и реальными текстами из ТЗ. Дизайн-система выведена из мокапа главной страницы.

Задача разработки: реализовать эти макеты как многостраничный сайт (или SSG/CMS) с общей шапкой, подвалом и переиспользуемыми блоками. Один тип страницы = один шаблон, наполняемый данными (отрасли, решения, кейсы, статьи).

## About the Design Files
Файлы в этом пакете — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие внешний вид и поведение, а **не production-код для копирования напрямую**. Задача — **воссоздать эти макеты в вашем окружении** (React/Next.js, Vue/Nuxt, Bitrix, Tilda-экспорт, обычный HTML+CSS — что принято в проекте), используя ваши паттерны и компонентную модель. Если стека ещё нет — выбрать подходящий фреймворк под многостраничный SEO-сайт (важен SSR/SSG: сайт заточен под Яндекс, см. раздел SEO).

Весь CSS дизайн-системы лежит внутри HTML-файлов в блоке `<helmet><style>` — его можно перенести в CSS/SCSS проекта напрямую (список утилит и токенов ниже).

## Fidelity
**Средняя (medium-fidelity).** Финальные цвет, типографика, компоненты, отступы и адаптив заданы и готовы к переносу. Изображения — **плейсхолдеры** (диагональная штриховка с подписью моноширинным шрифтом, напр. «фото · бизнес-центр», «скриншот · интерфейс платформы»); их нужно заменить реальными фото/скриншотами. Тексты — **финальные, из ТЗ**, можно использовать как есть.

### 01 — Главная `/`

Блоки: hero (тёмный, заголовок + подзаголовок + 2 кнопки + виджет «единый центр управления» с 4 показателями 142/14/98,2%/24 + логобар производителей) → «Какие задачи вы хотите решить?» (6 карточек) → «Как проходит внедрение» (6 шагов, лента) → тёмная плашка результатов (5 цифр: до 30% / до 80% / 98%+ / 24/7 / 100%) → «Кейсы и результаты» (4 карточки) → «Отрасли» (12 плиток) → блок платформы (тёмный, 6 функций) → финальный CTA + 3 плашки доверия.

## ROI-калькулятор — логика

**Поля ввода** (state): тип объекта (select), площадь м² (слайдер 500–30000, шаг 500), режим уборки (сегмент: дневная/ночная/круглосуточная), число уборщиков (слайдер 1–20), ставка ₽/мес (слайдер 30000–120000, шаг 5000), модель (сегмент: Аренда RaaS / Покупка).

**Формула** (демо-константы — заменить реальными из экономики компании):
```
modeFactor       = (круглосуточная ? 1.6 : 1)
robots           = max(1, ceil(площадь / 5000 * modeFactor))
ФОТ_год (ручной) = уборщики * ставка * 12 * 1.3      // 1.3 = налоги/отчисления
operatorYear     = 120000 * 12 * 1.3
opShare          = operatorYear / 15                 // 1 оператор ведёт ~15 объектов
elecPerRobot     = 30000 ₽/год

Аренда:  robo = 75000*12*robots + elec*robots + opShare
Покупка: amort = 1_800_000 / 5 (срок службы, лет)
         service = 1_800_000 * 0.12
         robo = (amort + service + elec) * robots + opShare
         invest = 1_800_000 * robots

economy   = max(0, manual - robo)
savePct   = round(economy / manual * 100)
payback   = round(invest / (economy/12))   // только для покупки, мес.
```
**Результат** (правая синяя панель): экономия ₽/год (крупно), % снижения [+ окупаемость мес. для покупки], 2 сравнительных бара (ручной vs робот), строки: роботов на объект / ФОТ сейчас / затраты с роботом, CTA «Получить детальный расчёт и КП» → форма (захват лида).
**Проверка на дефолтах** (Офис, 5000 м², ночная, 2 уборщика, 60000 ₽, Аренда): экономия ≈ 817 200 ₽, снижение ≈ 44%. Покупка: ≈ 61%, окупаемость ≈ 19 мес.
В проде: настроить цели в Яндекс.Метрике на использование калькулятора и отправку формы.

## Interactions & Behavior
- **Навигация в макете-ревью:** плавающий индекс справа (`.dx`) со ссылками-якорями на все 12 типов; на реальном сайте это обычная межстраничная навигация.
- **Калькулятор:** реактивный пересчёт при любом изменении слайдера/сегмента (без submit). Слайдеры — нативный `input[type=range]` со стилизованным thumb.
- **Наведение:** карточки — граница → blue; кнопки — фон темнеет; ссылки-стрелки.
- **Форма контактов:** валидация обязательных полей + чекбокс согласия (обязателен по закону). Минимум полей = выше конверсия.
- **Фильтр кейсов:** пилюли, активная подсвечена синим.

## Responsive
Breakpoints: **≤1100px** — шапка сворачивается в бургер. **≤1000px** — плавающий индекс скрыт. **≤940px** — все сплит-2 и многоколоночные сетки → 1–2 колонки, шаги 6→3, плитки 6→3, отступы секций уменьшаются. **≤600px** — почти всё в одну колонку, уменьшенные заголовки. Mobile-first важен: Яндекс/Google оценивают мобильную версию.

## SEO / технические требования (из ТЗ, для разработчика)
- ЧПУ-URL (см. каждый тип), один H1 на страницу, уникальные Title/Description.
- Schema.org JSON-LD: Organization (шаблон), LocalBusiness (Контакты), BreadcrumbList (вложенные), Service (решения/услуги), Product (продукты/платформа), FAQPage, Article (база знаний).
- Хлебные крошки (визуально + разметка), canonical, robots.txt + sitemap.xml, alt у изображений, Open Graph.
- Core Web Vitals в зелёной зоне; HTTPS; кастомная 404.
- Единые контакты (NAP) во всех местах; карточка Яндекс.Бизнес.
- Метрика: цели на клики CTA, отправку форм, использование калькулятора, коллтрекинг.
